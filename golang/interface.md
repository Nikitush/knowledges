В целом это описание некоторого контракта/сам контракт, которому должны удовлетворять структуры, чтобы считаться подходящими под тип, описанный интерфейсом, который они имплементируют
Если по простому, то интерфейс описывает только сигнатуры структур и методов, без реализации и ждёт, что кто-то их имплементирует, чтобы соответствовать интерфейсу
А так как в go утиная типизация, то явно указывать, как в java, например, что мы реализуем интерфейс не надо, это делается под капотом

## Что же там внутри
Сама структура интерфейса проста
```go
type iface struct {
	tab  *itab
	data unsafe.Pointer
}
```

Здесе `tab` — это указатель на `Interface Table` или `itable` — структуру, которая хранит некоторые метаданные о типе и список методов, используемых для удовлетворения интерфейса
`data` — указывает на фактическую переменную с конкретным (статическим) типом
`Если не вдаваться в подробности, то в поле `tab` у нас хранится информация о конкретном типе объекта, который был преобразован в интерфейс. А в поле `data` — ссылка на реальную область памяти, в которой лежат данные изначального объекта, в нашем случае Василия. Поэтому библиотека рефлект, когда хочет получить настоящий исходный тип объекта интерфейса, идёт в это поле `tab` и получает информацию о типе там.` -- под вопросом
Как выглядит `itab` для наглядности
```go
// layout of Itab known to compilers
// allocated in non-garbage-collected memory
// Needs to be in sync with
// ../cmd/compile/internal/reflectdata/reflect.go:/^func.WriteTabs.
type itab struct {
	inter *interfacetype
	_type *_type
	hash  uint32 // copy of _type.hash. Used for type switches.
	_     [4]byte
	fun   [1]uintptr // variable sized. fun[0]==0 means _type does not implement inter.
}
```
## Приколы
Пустой интерфейс, он же `interface{}`, он же `any`
Ему удовлетворяет вообще любой тип, прям что угодно, так как этот интерфейс не просит ничего реализовывать
Поскольку у пустого интерфейса нет никаких методов, то и itable для него просчитывать и хранить не нужно — достаточно только метаинформации о статическом типе + ссылку на конкретный объект в памяти

Nil интерфейс отдельный прикол
Упрощенно переменную типа interface можно представить как пару (type, value) -- где value - конкретное значение(указатель на него), а type - тип этого значения
И тут встает вопрос, когда переменная интерфейса считается nil?
Ответ прост, до тех пор, пока оба из пары (type, value/tab, data) равны nil, как только один из них не nil, то интерфейс тоже не nil
```go
package main  

import "fmt"

type A interface {
	Say(string)
}

type B struct{}  

func (B) Say(s string) {
	fmt.Println(s)
}

func main() {
	var a A
	fmt.Println(a == nil)
	var b *B
	fmt.Println(b)
	a = b
	fmt.Println(a == nil)
}
```

```bash
go run ex.go 
true
<nil>
false
```
