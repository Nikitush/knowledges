>[!info]
>Мапа в go, как и слайс, является ссылочным типом, поэтому с ней происходит тоже самое при передаче в функцию и похожие трюки, не забывать про это и помнить про копирование в нужных местах

Мапа в go представляет из себя хэш-таблицу/словарь/карту/ассоциативный массив и несет много интересного
Вот так выглядит неверное объявление мапы
```go
package main

import (
	"fmt"
)

func main() {
	var sl map[string]int
	fmt.Println(sl)
	fmt.Println("len:", len(sl))
	fmt.Println(fmt.Sprintf("%p", sl))
}
```

```bash
go run ex.go
map[]
len: 0
0x0
```

После такого мы ничего не сможем с ней сделать, например
```go
package main

import (
	"fmt"

func main() {
	var sl map[string]int
	fmt.Println(sl)
	fmt.Println("len:", len(sl))
	fmt.Println(fmt.Sprintf("%p", sl))
	sl["1"] = 1
}
```

Для мапы доступны следующие возможности:
- Вставка
- Удаление
- Поиск
```go
package main

import (
	"fmt"
)

func main() {
	sl := make(map[string]int, 10)
	fmt.Println(sl)
	fmt.Println("len:", len(sl))
	fmt.Println(fmt.Sprintf("%p", sl))
	sl["1"] = 1 // Вставка
	sl["2"] = 2
	fmt.Println(sl)
	fmt.Println("len:", len(sl))
	fmt.Println(fmt.Sprintf("%p", sl))
	delete(sl, "2") // Удаление
	value, ok := sl["1"] // Получение
	fmt.Println(value, ok)
	value, ok = sl["2"] // Получение
	fmt.Println(value, ok) // Тут вернется дефолтное значение типа int, так как ключ не был найден, поэтому собственно и false
}
```

```bash
go run ex.go
map[]
len: 0
0xc000090090
map[1:1 2:2]
len: 2
0xc000090090
1 true
0 false
```

Также по мапе можно итерироваться, но так как мапа это не упорядоченная коллекция, то каждый раз результат будет разным
Это можно обойти сделав рядом слайс с ключами, куда мы их будем последовательно ложить, а потом их читать
```go
package main

import (
	"fmt"
)

func main() {
	sl := map[string]int{"1": 1, "2": 2, "3": 3}
	fmt.Println(sl)
	fmt.Println("len:", len(sl))
	fmt.Println(fmt.Sprintf("%p", sl))
	for key, value := range sl {
		fmt.Println(key, value)
	}
	fmt.Println()
	for key, value := range sl {
		fmt.Println(key, value)
	}
}
```

```bash
go run ex.go
map[1:1 2:2 3:3]
len: 3
0xc000100090
3 3
1 1
2 2

1 1
2 2
3 3
```

Не стоит растить мапу при итерации по ней, это приведет к печали, так как ключи будут попадать в мапу и мы и по новым(добавляемым) ключам будем итерироваться
```go
package main

import (
	"fmt"
)

func main() {
	sl := map[string]int{"1": 1, "2": 2, "3": 3}
	fmt.Println(sl)
	fmt.Println("len:", len(sl))
	fmt.Println(fmt.Sprintf("%p", sl))
	for key, value := range sl {
		sl["1"+key] = value
	}
	fmt.Println(sl)
}
```

```bash
go run ex.go
map[1:1 2:2 3:3]
len: 3
0xc000090090
map[1:1 11:1 11112:2 1112:2 1113:3 112:2 113:3 12:2 13:3 2:2 3:3]

go run ex.go
map[1:1 2:2 3:3]
len: 3
0xc000100090
map[1:1 11:1 111:1 12:2 13:3 2:2 3:3]
```

Для исправления стоит скопировать мапу
```go
package main

import (
	"fmt"
)

func main() {
	sl := map[string]int{"1": 1, "2": 2, "3": 3}
	fmt.Println(sl)
	fmt.Println("len:", len(sl))
	fmt.Println(fmt.Sprintf("%p", sl))
	sl1 := make(map[string]int, len(sl))
	for key, value := range sl {
		sl1[key] = value
	}
	for key, value := range sl {
		sl1["1"+key] = value
	}
	fmt.Println(sl)
	fmt.Println(sl1)
}
```

```bash
go run ex.go

len: 3
0xc000090090
map[1:1 2:2 3:3]
map[1:1 11:1 12:2 13:3 2:2 3:3]

go run ex.go
map[1:1 2:2 3:3]
len: 3
0xc000090090
map[1:1 2:2 3:3]
map[1:1 11:1 12:2 13:3 2:2 3:3]
```

## Немного о map'е под капотом
Есть некоторые столпы хэшмапы:
- Хэш-функция -- под ней понимают функцию, которая принимает значение (ключ) неопределенного размера и возвращает значение фиксированной длины, в случае c Go она возвращает `uint64`, одно из главных свойств - стабильность. Для одного и того же переданного значения она должна возвращать один и тот же результат
- Бакет -- так называемая структура данных, в которой хранятся ключи и значения в мапе, в некоторых реализациях hashmap в одном бакете хранится одно значение, а в других - несколько, например, в Go данные внутри бакета хранятся в массиве, и в одном бакете может быть до восьми элементов
- Коллизия -- так как хэш-функция не идеальна, передав в нее два разных значения мы можем получить один и тот же результат, в случае с бакетами нам нужно два разных значения положить в один и тот же бакет, это называется коллизией, для реализации hashmap необходимо иметь алгоритм их разрешения, существует несколько таких алгоритмов (стратегий)
	- Closed addressing(закрытая адресация) -- храним элементы с одинаковым хэшем с помощью дополнительных структур данных, таких как: связный список, двоичное дерево, массив и др, используется в следующих языках: Go, Java, Scala
	- Open addressing(открытая адресация) -- в бакете хранится только одно значение, при возникновении коллизии выбирается следующий свободный бакет по какой-либо формуле, такая стратегия используется в Python, Ruby, Rust, C++ и др
	- Perfect hashing(идеальное хэширование) -- выбирается такая хэш-функция, при которой не будет коллизий, подбирается для статичного, заранее известного набора ключей
- Фактор заполняемости -- это число (порог), превысив которое считается, что нужно увеличить количество бакетов (обычно вдвое) для сохранения константной скорости
Рассмотрим алгоритм по шагам
- Передаем ключ `"The Matrix"` в хэш-функцию и получаем `uint64` - 18002143618149980261
- Вычисляем маску для наших бакетов, она равна `n-1`, где n - количество бакетов, в примере 4 бакета, а маска равна 3
- Вычисляем номер бакета, в котором сохраним наше значение, для этого используем битовое _"и"_: `hash & mask` == `18002143618149980261 & 3` == `01 & 11`(отбросили нули) = `01`, что рано 1 в десятичной системе счисления
- Идем в бакет по индексу 1 и перебором проверяем массив на наличие нашего ключа, если находим совпадение по ключу, то перезаписываем значение, иначе добавляем в первое свободное место
Из интересного:
- Нельзя получить адрес элемента мапы(ну или лучше не пытаться), так как при росте мапы и достяжении load factor == 6,5 происходит эвакуация данных, которая занимает какое-то время, в течении которой старые и новые бакеты связаны, и элементы переезжают между ними, а кол-во новых бакетов в двое больше старых
- При каждом создании мапы генерится seed(можно сказать соль) для рандомизации хэш-функции, это сделано для безопасности, так как зная хэш-функцию можно подобрать такие ключи, что все значения попадут в один бакет и мы получим линейную скорость поиска
- При коллизиях используется стратегия сlosed addressing, мы перебираем все ячейки бакета (их 8) и ищем первое свободное место
- При коллизиях используется стратегия _сlosed addressing._ Мы перебираем все ячейки бакета (их 8) и ищем первое свободное место
